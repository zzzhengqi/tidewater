# Tidewater（zzzhengqi fork）进度记录

开工前先读这份文件，收工时更新它。

## 产品定位（不变的约束）

- "个人私密世界"：核心是自由调时间 / 太阳方位 / 海浪，潜水、开船、自由相机飞行。
- 钓鱼是保留的**可选**玩法之一，不能让项目变成"只是钓鱼游戏"。不加金币驱动的新系统、排行榜、强制任务。
- 所有用户可见文字走多语言机制；新增 key 必须同时补全所有已支持语言。
- 不引入联网素材；保持性能；不让已有功能退化。
- 每个阶段结束 git commit，`npm run build` 与 `npm test` 必须通过。

## 上游引擎结构概述

- `src/engine/`：自研渲染引擎。CPU 侧是与 three.js 接口相近的数学 / 场景 / 几何（`Vector3`、`Mesh`、`BufferGeometry`…），
  GPU 侧（`engine/webgpu.js`）是 `GPU` 单例、`Texture` / `RenderTarget`、`UniformBlock`、`ShaderModule`（WGSL 片段按前缀共享）、
  `ComputeKernel`、`Material`、`MeshRenderer`、`FullscreenPass`、阴影 `SunShadows`、蒙皮 `SkinnedModel`。移植约定见 `docs/PORTING.md`。
- `src/App.js`：启动顺序（大气 → 地形 → 村庄 → 植被 → 海浪 → 珊瑚礁 → 海洋 → 着色器编译 → 预热），每帧更新与渲染。
- 系统目录：`ocean/`（FFT 海洋、岸浪、碎浪、航迹、焦散、水下光照）、`sky/`、`world/`、`post/`（AO、TAAU、动态模糊、泛光、镜头光晕…）、
  `materials/`、`player/`（步行、游泳、开船、自由相机）、`audio/`、`fx/`。
- `src/game/`：钓鱼玩法。`Game.js`（总控、提示、吐司）、`GameHUD.js`（钱包 / 冷藏箱 / 油量 / 声呐、搏鱼条、渔获卡片、冷藏箱面板、
  鱼摊与船具店面板）、`Guide.js`（新手引导 3 张卡片 + 一次性提示）、`Minimap.js`、`FishTable.js`（18 种鱼）、`Gear.js`（升级）、
  `Vendor.js` / `FishStand.js` / `Chandlery.js`（乔与玛尔塔）、`FishPortrait.js`（渔获卡片里的实时 3D 鱼）。
- `src/ui/`：`UI.js`（通用设置面板组件、HUD、帮助、开始画面、加载器）、`AppUI.js`（把设置项绑到 App）、`i18n.js` + `locales/`（多语言）。
- `index.html`：加载器的静态标记（带 `data-i18n`）。
- 测试：`test/i18n-check.mjs`、`test/i18n.test.mjs`、`test/game-logic.mjs`、`test/engine-smoke.mjs`（Node 里用 Dawn 无头 WebGPU 跑引擎冒烟）。

## 多语言机制

支持语言：`en`（源语言）、`zh-CN`、`ja`、`ko`、`ar`。列表在 `src/ui/i18n.js` 的 `languages`。

### 运行时（`src/ui/i18n.js`）

- `t( key, params )`：取当前语言的文字，`{name}` 占位符由 `params` 填充。当前语言缺这个 key（或为空）时**回退到英文并在控制台警告一次**；
  英文也没有则返回 key 本身并警告。
- `phrase( english )`：把一段英文源文字翻译成当前语言（按 en.js 的值反查 key）。只在这些命名空间里反查：
  `language ui settings options phase mode prompt toast loader error`，避免把按键 `E`、数字之类误翻。用于：
  - 设置面板 / 侧栏：`AppUI.js` 用英文标签搭建，`UI.js` 里的 `MutationObserver` 把面板里的文本节点和
    `aria-label / data-tip / data-tip-hint / title / placeholder / aria-valuetext` 原地翻译，切换语言时从记录的英文原文重新翻译（沿用旧 fork 的做法）。
  - HUD 的模式标签（`setMode`）、交互提示（`setPrompt`，玩家模块传英文）、吐司（`toast`）、加载状态（`setLoading`）。
- `setLanguage( code )`：保存到 `localStorage['tidewater.ui.language']`，更新 `<html lang>`，重刷所有 `data-i18n` 静态标记，通知订阅者。
- `onLanguageChange( fn )`：订阅切换；`UI`、`GameHUD`、`Guide`、`Minimap` 都订阅了，切换后已打开的面板 / 卡片 / 引导会立即重绘。
- 默认语言：有保存的选择用保存的；否则按浏览器语言列表，`zh*` → `zh-CN`，`ja` / `ko` / `ar` 各自对应，其余英文。
- `localizeStatic( root )`：`data-i18n="key"`（写 innerHTML）与 `data-i18n-attr="aria-label:key;title:key"`。
- 语言选择器在设置面板标题栏（`H` 打开）。阿拉伯语时设置标签、钓鱼面板、引导卡片为 RTL（`ui.css` 末尾的 `[data-lang='ar']` 规则）。

### 新增 / 修改一条界面文字要改哪里

1. 在 `src/ui/locales/en.js` 加 key（按命名空间分组：`ui.` 面板外壳、`settings.` 设置项、`hud.` HUD、`prompt.` 交互提示、
   `toast.` 吐司、`loader.` 加载器、`help.` 帮助页、`start.` 开始画面、`fish.<id>` 鱼名、`gear.<track>[.<level>]` 装备、
   `vendor.<id>.*` 商贩、`catch.` 渔获卡片、`inv.` 冷藏箱、`stand.` 鱼摊、`shop.` 船具店、`game.` 钓鱼吐司、`guide.` / `tip.` 引导、
   `unit.` 单位、`dir.` 方位、`key.` 按键名、`keys.` 帮助页键位说明、`wheel.` 轮盘、`equip.` 装备项、`options.` 玩法选项、`error.` 错误）。
2. **同一次提交**里在 `zh-CN.js`、`ja.js`、`ko.js`、`ar.js` 补上同一个 key，占位符 `{x}` 必须一致。值可以含 `<b> <kbd> <small> <p>`。
3. 代码里：
   - 游戏 / HUD 代码直接 `t( 'key', { … } )`（`Guide.js`、`Minimap.js`、`UI.js` 里导入为 `tr`，避免和局部变量 `t` 冲突）。
   - 设置面板：`AppUI.js` 照常写英文 `label` / `tooltip`，只要 en.js 的 `settings.*` 里有同样的英文就会被翻译。
   - 玩家提示 / 模式 / 吐司 / 加载状态可以传英文（会走 `phrase()`），但英文必须在对应命名空间里有条目。
   - 单位用 `src/game/text.js` 的 `kg() cm() metres() litres() money()`，中文显示公斤、厘米、米、升。
4. `npm run i18n:check`（已并入 `npm test`）会报：某语言缺 key、多余 key、空翻译、占位符不一致、代码里 `t('…')` 用了不存在的 key、
   走 `phrase()` 的英文没有条目、`GameHUD / Guide / Minimap` 的标记里残留英文句子。
5. `npm run i18n:preview` 重新生成 `test/i18n.html`，直接用浏览器打开（不需要 WebGPU、不需要服务器），底部工具栏切语言和画面。

新增一种语言：在 `languages` 里加一行，新建 `locales/<code>.js`（所有 key），在 `i18n.js` 顶部 import 并放进 `locales`。

## 轮盘与装备注册表

- `src/ui/RadialWheel.js`：通用轮盘组件，可以挂多个（以后的相机轮盘就是再 new 一个，换一个注册表和 onSelect）。
  ```js
  new RadialWheel( ui, {
    title: 'wheel.equipment',              // 中央小标题的 i18n key
    registry,                              // ItemRegistry
    current: () => equipment.current,      // 当前手持（显示太阳色小圆点）
    onSelect: ( id ) => equipment.set( id ),
    codes: codesOf( 'equipment' ),         // 打开 / 打开后顺时针切换
    closeCodes: [ …移动键 ],               // 按下即关闭、不切换，按键继续传给游戏
    canOpen: () => true,                   // false 不打开；返回 i18n key 则弹出该提示
  } );
  ```
  打开时屏幕轻微暗化；鼠标移动驱动虚拟光标（不释放指针锁），死区外按角度选扇区；左键或 Enter 确认；
  轮盘打开期间吞掉鼠标和它自己的按键，镜头不转、鱼竿不会误抛。语言切换时文字即时更新。
  完整操作：R / 鼠标滚轮 顺时针（Shift+R、上滚为逆时针）；数字 1–9 直接装备对应扇区（数字印在扇区上，只在轮盘打开时有效，
  不占用游戏按键）；按住 R 超过 0.32 s、指向后松开 = 装备；Esc / 右键 / 移动键 取消。每个扇区显示图标、名称和编号，
  中央显示大图标、名称、状态标签（当前手持 / 此处不可用）和一句提示；不可用的项目也能指向，中央会说明原因。
- `src/core/Equipment.js`：`ItemRegistry` + `Equipment`。`app.equipment` 在 `App` 构造时创建，内置"空手"（id `hands`，默认）。
  `Equipment.set( id )` 先 `unequip` 当前装备再 `equip` 新装备，任意时刻只有一件；当前装备 `busy()` 时拒绝切换（搏鱼中、渔获卡片中）；
  每帧 `Equipment.update()`：当前装备不再可用（游泳、开船、自由相机、钓鱼关闭）时静默收起、回到空手。
- 鱼竿在 `src/game/Game.js` 构造函数里注册，复用上游的 `rod.equip()` / `cancelLine()`，钓鱼逻辑本身没改，只改了入口。

### 新增一个装备项（例如滑翔伞）

1. 在合适的模块里：
   ```js
   app.equipment.registry.add( {
     id: 'glider', label: 'equip.glider', hint: 'equip.gliderHint', icon: 'glider', order: 20,
     visible: () => Options.get( 'gliding' ),   // 可选：不满足就不出现在轮盘上
     available: () => player.mode === 'walk',   // 可选：不满足就灰显、不能选
     unavailableHint: 'equip.gliderUnavailable', // 可选
     busy: () => glider.inFlight,               // 可选：飞行中不能收起
     equip: () => glider.show(), unequip: ( { silent } ) => glider.hide(),
   } );
   ```
2. `src/ui/icons.js` 的 `PATHS` 加 `glider` 图标（24×24 描边）。
3. 五个语言文件都加 `equip.glider` / `equip.gliderHint`（以及 unavailableHint），跑 `npm run i18n:check`。
4. 不需要改轮盘、不需要新键位。

## 冲浪（`src/surf/`）

- `SurfboardSpec.js`：五种板型的数据（软板 softtop、长板 longboard、短板 shortboard、鱼板 fish、枪板 gun），每种有独立的
  尺寸、平面轮廓（最宽点、板头圆度、板尾宽、尾型 square/squash/round/pin/swallow）、翘度、鳍型（single/twin/thruster/quad）、
  止滑垫 / 中线木条、浮力、划水速度、转向上限、最高速度、`catchEase`（起乘窗口加宽）、`stability`（白水里撑得更久、晃得更少）、
  `bigWave`（大浪陡坡上更"咬浪"、小浪里吃亏）和默认配色。默认板是软板（最易上手）。加新板型只需在这里加一项（再补五个语言的名称和说明）。
  板型对手感的影响在 `Surfing.js`：`_catchT()`（起乘阈值）、`_ride()` 的 `fit`（浪面推力随浪高和板型变化）、白水落水时间、晃动幅度、漂浮高度。
- `BoardGeometry.js`：程序化板子网格（板面 / 板底两张网格在边缘顶点相接，尾端封口，按鳍型生成鳍），以及图片贴图的映射数学
  `decalAffine`；`BoardMaterial.js`：`BoardLook`（板面 / 板底 / 边条 / 鳍颜色、5 种图案、图片贴图，全部是材质 uniform，改了立刻生效）；
  `BoardStore.js`：方案的保存（见下方"板库"）；`BoardImage.js`：本地图片导入；`BoardPreview.js`：板库里的 3D 预览。
- `Surfing.js`：冲浪控制器，状态 `carry`（岸上夹在腋下）→ `paddle`（下水 0.65 m 以上或游泳时自动趴板）→ `ride`（站立滑行）
  → `loose`（落水后游泳，板子用脚绳拴在 2.6 m 内漂着，游过去碰到自动上板）。不占新字母键：WASD / Shift / Space 复用。
  - 接浪（趴板时按 Space）：板下必须是正在变陡或刚破碎的浪的前坡（相位 −0.18..0.06、坡度 ≥ 0.05、破碎进度 −3.5..1.2、浪高 ≥ 0.35 m），
    板头与浪向夹角 ≤ 53°，沿浪向速度 ≥ 0.38 × 浪速。失败分四种反馈：没有可接的浪 / 白水 / 方向不对（板被浪推着横移并转 0.7 rad）/
    太慢（浪把板往前送一下后从身下滚过去）。
  - 滑行：重力沿浪面坡度下滑 + 浪面把你拉向它的速度（在浪峰前的"甜点"相位处等于浪速，太靠前会变慢让浪追上）；A/D 是**压板边**
    而不是打舵：身体倾斜（最大 0.65 rad，`leanRate` 4/s）把板子压到板边上，转弯角速度 = g·tan(倾角)/速度（即真实刻弧转弯的半径 v²/(g·tanθ)），
    浪面越陡板边咬得越紧；腾空时不能转向、不能压浪。W 压浪加速，S 减速，板轨抓水（侧滑迅速衰减）。
  - 漂浮：板子永远不会低于身下的水面（板头、板尾、两侧板边、中心五点取最高的接触面），水面上升时把板托起，水面下降时板子最多以
    重力加速度跟着落下；浪面下落得比重力还快（陡浪的背面 / 浪峰抛出）时板子短暂腾空，然后被水面重新接住（落下时溅起水花）。
  - 落水：白水下超过 0.3 s（被白水卷翻）、浪已经从身后过去或几乎停住超过 1.4 s（浪消退了）、在礁石 / 陡峭岩底上方水深 < 0.6 m（撞上礁石）、
    主动按 Space（跳下）。在沙底浅滩水深 < 0.45 m 则平稳结束、站起来夹着板。
  - 表现：板头水花（转向外侧）、板尾落下即成泡沫的水滴（尾迹）、白水里板下的水雾、划水时的手部水花（都走共享的 Spray 粒子池，
    每帧最多 4 次请求，且在池子请求过多时让路）；只有第一人称（趴板眼高 0.8 m、站立 1.75 m，鼠标转头），没有第三人称，V 在冲浪时无效。
  - 自由相机 F：冲浪时可用，滑行在没有输入的情况下继续模拟；再按 F 回到板上的相机。拍照模式 P：只隐藏界面，冲浪不受影响。
  - 设置 → 海洋 → 海况预设新增"冲浪浪况"（Groundswell）：浪高约 1.3 m（`surf` 0.65）、周期 13 s、离岸微风 4 m/s（风向按岛的涌浪方向自动算成离岸）。
- `src/ocean/ShoreSampler.js`：岸浪的 CPU 采样器，逐行移植自 `ShoreWaves.js` 的高度路径（相位、波群振幅、破碎参数、横截面、
  白水）和 `waterQueryHeightAtXZ` 的欧拉反解（2 次不动点迭代）。每次调用读取实时 uniform，所以设置面板 / 预设改浪高、周期、
  风向时 CPU 与 GPU 同一帧生效。FFT 外海浪不在 CPU 上重算：冲浪用玩家已有的 GPU 查询算出"慢残差"（GPU 总高度 − 同一点同一时刻的 CPU 岸浪），
  低通后叠加；破碎浪本身不依赖回读。
  - 为了让 CPU 与 GPU 一致，把着色器里每个浪的随机数 `shoreHash1` 从 `fract(sin(x)*43758)`（大参数下各 GPU 结果不同）换成整数哈希（PCG），
    CPU 端逐位相同。统计特性不变，只是具体每个浪抽到的随机值不同。
- 每帧最多 5 个采样点（中心、板头、板尾、残差（回读到达时）、漂浮的板），远低于 8 点预算。

## 冲浪辅助（玩法选项 `surfAssist`，默认开）

- 趴板在水里时，岸浪逐渐变大、组浪更平均（`ShoreWaves` 新 uniform `surfBoost`：振幅变为 max(1.3 × 设置值, 0.75 m)，即默认海况下外海浪高约 1.5 m（原来约 0.7 m）、小浪拉平，4 s 渐入、离开水面后 8 s 渐出，
  CPU 采样器同步读取，CPU / GPU 一致性测试新增一组）。这只在冲浪时影响海面，关闭辅助或上岸后回到你设置的海况。
- 起乘窗口放宽（`SURF_ASSIST`：最小浪高 0.18 m、相位 −0.34..0.14、破碎进度 −12..1.5（还没破的涌浪也能接）、对齐 ≈80°、不要求速度；站起来时板头自动转向浪的方向最多 0.6 rad）。
- **最佳时机提示**：屏幕中央出现大号「空格 起乘！」并伴随一声"嗖"——此刻按空格要么立即起乘，要么在浪到达时自动起乘（3 s 内）。一直按住空格也会在可以起乘的瞬间站起来。
- **提前按空格会等浪**：下一道能冲的浪在 3 s 内到达时，按下空格不会失败，而是"准备好了"，板头自动转向浪的方向，浪一到身下就站起来。
- 划向接近中的浪面时，浪会把你往前托（`lift`）。
- **屏幕引导**（趴板时，屏幕下方）：箭头指向板头该对准的方向（相对你的视线；在白水里指向外海），圆环随下一道浪接近而填满，一句提示：
  朝破碎的浪划 / 白水区先划出去 / 等待够大的浪 / 下一道浪 N 秒后到 / 转身对准沙滩 / N 秒后浪到：划水然后按空格 / 准备好了 / 就是现在！按空格。
  下一道浪的位置和时间来自板子中心的相位（再多采样 1 个点看它多大），每帧采样仍 ≤ 8 点。
- 实测（用户的 Chrome，默认海况，6 个破浪区位置，各 60 s，板头对准、全力划水）：可起乘时间占比 4.2% → 11.1%，起乘窗口 3.3 → 8 次/分钟；
  按引导操作（提示划水时按空格）起乘成功率 8% → 70%，约 4.7 次/分钟。

## 板库（轮盘冲浪板扇区旁的"板库"按钮，或 设置 → 玩法 → 冲浪板 → 板库）

- 没有字母键。轮盘：冲浪板扇区外侧有一个小按钮，光标移过去高亮、左键打开（点扇区本身仍是装备冲浪板）。`RadialWheel` 支持任意装备项带
  `action: { icon, label, hint, run }`。滑行中轮盘本来就不能打开（装备忙）；板库打开时轮盘不响应。
- 面板（`src/ui/BoardLibrary.js`）：左侧选板型（名称、尺寸、一句说明、5 项能力条：速度 / 转向 / 划水 / 易接浪 / 大浪）和"我的方案"
  （新建、重命名（行内输入）、删除（再点一次确认）、导出 JSON、导入 JSON）；右侧 3D 预览（拖动旋转、"翻到另一面"、未触碰时缓慢自转）和外观：
  板面 / 板底 / 边条 / 尾鳍颜色、图案（纯色 / 中线条纹 / 渐变到板头 / 边缘渐变 / 板头色带）+ 图案颜色、图片（选择文件或直接拖进面板；
  贴板面 / 板底 / 隐藏；缩放 100–400%、旋转 ±180°、左右 / 前后移动、镜像）。打开时释放鼠标、游戏输入暂停；Esc 或点面板外关闭。
- **预览与游戏一致**：预览和游戏里的板子共用同一份几何体和同一个材质（`BoardLook`），每次修改都同时作用于两者；滑行中换板型会在这次滑行结束后生效。
- **图片**：只接受 png / jpg / webp，原文件 ≤ 15 MB，全部在浏览器本地处理（不上传）；用 canvas 缩到最长边 ≤ 1024 px 后存为 WebP（不支持时 PNG），
  保存前若仍超过限制会逐级降低尺寸 / 质量，实在太大给出提示。格式不对、读不出、太大、存储不够都有多语言提示。
- **贴图映射**：按板子的平面（俯视）投影，图片以"覆盖"方式铺满板子外接矩形，并且在任何旋转角度下都放大到刚好盖住旋转后的矩形；缩放只能 ≥ 100%，
  移动量是"放大后多出来的余量"的比例，所以无论怎么调都**不会露出空白**；平面投影没有拉伸（测试检查横纵比例一致）；轮廓外的部分天然被裁掉（几何只在轮廓内）。
  板底的图片从下方看是正的。边条色带（板边弯下去的部分）盖在图片上，避免侧面的拉伸。
- **保存**：`localStorage['tidewater.boards']`（方案列表与当前方案）+ 每张图片单独一个 `tidewater.boardImg.<id>`；所有读写都包 try/catch，
  配额不足 / 隐私模式不会崩溃，会提示且不会留下半保存的数据。刷新后板型、外观、图片都在。导出文件 `名称.tidewater-board.json`（含图片），导入时逐项校验，
  不认识的字段回到默认值。
- 测试 `test/boards.test.mjs`：五种板型参数各不相同、网格有限且尺寸正确、燕尾 / 尖尾 / 圆头、鳍在板底下方；图片在所有旋转 / 缩放 / 移动 / 镜像组合下都盖住轮廓、无拉伸；
  方案保存 / 重载 / 重命名 / 删除 / 脏数据修复 / 配额满 / 存储不可用 / 导出导入往返；图片文件类型与大小检查。

## 画质预设与自适应分辨率（设置 H → 性能 → 画质，`src/core/Quality.js`）

- **画质预设**：低 / 中 / 高 / 极高（手动改渲染比例、阴影、水面反射后显示"自定义"）。保存在 localStorage `tidewater.graphics`，下次打开自动应用。
  | 预设 | 输出像素密度 | 最高内部渲染比例 | 阴影 | 水面反射 |
  |---|---|---|---|---|
  | 低 | 1× | 65% | 关 | 关 |
  | 中 | 1× | 85% | 开 | 关 |
  | 高（默认） | 1× | 100% | 开 | 开 |
  | 极高 | 屏幕真实像素密度（最多 2×） | 100% | 开 | 开 |
  "极高"是给高配设备用的：高分屏（笔记本、Mac、4K）上按真实像素渲染，画面明显更锐利，GPU 负担也最大；配合自适应分辨率，内部分辨率会自动降到 GPU 跟得上的程度。
- **自适应分辨率**（默认开）：用 GPU 时间戳（`src/core/GpuTimer.js`，每 10 帧采样一帧，异步读回）测量整帧 GPU 耗时；超过目标帧时间的 92% 时内部渲染比例每次降 5%（最低 50%），
  低于 62% 持续 3 秒时每次升 5%（不超过预设值）。浏览器不支持时间戳时只按帧时间往下调。手动拖"渲染比例"会关闭自适应。
- **目标帧率**：30 / 60 / 120 fps（默认 60）。
- **运行较慢提示**：最低比例下仍持续 6 秒明显低于目标帧率（游戏开始 15 秒后），每次打开最多提示一次：建议改用"低"预设，也可以在 玩法 中关闭冲浪。
- `?bench` / `?scale=` 下不读取保存的画质、不做自适应（测量需要固定条件）。
- 实时数据新增"每帧 GPU 耗时"。
- 实测（本机 Chrome，窗口 1746×796，devicePixelRatio 2.2，冲浪趴板视角，GPU 每帧）：低 8.6 ms、中 10.1 ms、高 12.8 ms、极高（3492×1592，内部 100%）30.6 ms；
  极高 + 内部 50% 为 12.3 ms（与"高"相当，但输出是原生分辨率）。改变内部比例那一帧多 1–2 ms CPU，无 GPU 尖峰。

## 船只翻覆（保留翻船概率）

物理不变，大的横浪仍可能把船掀翻。新增：船持续倾斜超过约 75° 达 1.5 s 判定为翻覆 → 驾驶 / 甲板上的人被甩进水里，并提示"船翻了：
游到船边按 E 扶正它"；游到船旁 6.5 m 内按 **E** → 船在 2.4 s 内保持航向扶正、浮回水线；任何时候都可以在 设置 → 玩法 → 船 →
"把船拖回码头"（翻覆、搁浅、漂远都适用，船上的人一起回来）。没有新增按键。

### 修复：切到冲浪板后黑屏且无法恢复 + 轮盘完善（2026-10-27）

- 现象（用户报告）：R 切到冲浪板后画面全黑，切回空手 / 鱼竿也不恢复。
- 排查：在本机内置浏览器里用真实流程（R 轮盘 → 冲浪板、走动、反复切换）没能复现切板黑屏；但同一构建曾有一次启动即黑屏、且关掉抗锯齿 /
  自动曝光 / 移除冲浪板都不恢复。和上一阶段构建对比确认是"粘住"的坏状态。"切回去也不恢复"说明有逐帧累积的缓冲区（时域抗锯齿历史、
  自动曝光）被一个 NaN 像素污染后永久保留；不同显卡后端对 NaN（如 normalize(0)）的处理不同，所以只在部分机器上出现。
- 修复：时域抗锯齿 `TemporalUpscale.js` 对运动向量、历史颜色、写回的颜色 / 锁定 / 亮度历史做有限性检查（按指数位判断，不会被编译器优化掉），
  非有限值丢弃；自动曝光 `PostFX.js` 的测光忽略非有限像素，曝光值非有限时保留上一个好值。正常像素的结果不变。
  另外冲浪板夹在腋下（贴近相机）时不投影，下水后才投影。
- 诊断：`main.js` 现在在 WebGPU 设备丢失或出现第一个 GPU 错误时弹出带原因的提示（多语言），若仍黑屏，请把提示文字告诉我。
- 已验证：构建、全部测试通过；内置浏览器真实游戏里新轮盘（截图）、数字键 / 滚轮 / Shift+R / 按住 R 松开、反复切换冲浪板 / 鱼竿 / 空手，画面正常。
- 未验证：用户机器上的黑屏是否就是 NaN 污染（本机无法复现）。若是设备丢失或着色器编译失败，新的提示会显示原因。
- **真正原因（随后在用户的 Chrome 里复现并修复）**：带着冲浪板走进水里、第一次趴板的那一帧，`_mount` 之后紧接着 `_applyPose`，
  但这时还从没采样过板下的水（`this.s` 为空），水面高度是 undefined → 板子高度、冲浪相机、玩家位置全部变成 NaN；
  相机是平滑插值的、玩家位置也不会自己恢复，所以切回空手 / 鱼竿也一直黑屏。之前的测试都是先游泳再上板，恰好避开了。
  修复：`_mount` 里立刻采样一次；`_applyPose` 水面非有限时退回玩家水面高度；冲浪相机遇到非有限值保留上一帧并重新初始化；
  `App.guardViewAndPlayer()` 每帧兜底：相机或玩家位置非有限时恢复到上一个正常值（控制台给出警告）。
  已在用户的 Chrome 中按"R 轮盘选冲浪板 → 走进海里"复现黑屏，修复后同一路径正常趴板划水、画面正常。

### 冲浪卡顿排查 + 画质预设 / 自适应分辨率（2026-10-27）

- **排查结论**：冲浪本身几乎不花性能（每帧 CPU +0.1 ms、GPU +0.2 ms；帧时间没有尖峰，CPU 最多约 6 ms）。"卡顿"来自上一轮的漂浮模型：
  板子每帧直接吸附到五点水面的最大值上，GPU 回读的噪声和接触点切换直接进入第一人称视角，视角的竖直加速度平均 12 m/s²、峰值 160–280 m/s²
  （真实涌浪远小于 1 m/s²），看起来就像掉帧。
- **修复**：
  - 板子改为浮力弹簧（1.7 Hz、阻尼 0.9，相当于人的体重压在这块板的水线面积上）：浮在脚下水面的平均高度，水只能推不能拉，水面下落快于重力时板子腾空；
    另有硬性下限：任何一点的板底最多浸水 3 cm，水面上涨再快也不会把板子压到水下。
  - 视角：眼睛在板子上方用"腿部"弹簧（1.6 Hz、临界阻尼，膝盖最多弯 22 cm）吸收快速颠簸，涌浪和下浪完整传递；头部只跟随板子 45%（站）/ 75%（趴）的俯仰横滚并平滑，
    地平线比板子稳。删除了由噪声加速度驱动的膝盖弯曲。
  - 实测（用户的 Chrome，60 Hz 步进，各 8 s）：视角竖直加速度 平均 / 峰值 外海趴板 11.7 / 164 → 0.88 / 10 m/s²，冲浪区站立 → 0.53 / 2.9 m/s²；

### 冲浪：浪更高、更快、可以侧身横向滑行（2026-10-28）

- 浪高：冲浪辅助的放大改为"至少 1.5 m 外海浪高"（振幅 max(1.3×, 0.75 m)），默认海况下 4 m 水深处海面起伏中位数 1.04 m → 2.65 m；冲浪时你会被明显地托起、放下。
  CPU / GPU 一致性测试的 surfBoost 一组仍在 3 mm 以内。
- 速度：起乘速度 1.1 × 浪速、浪面带速目标 1.12 × 浪速、带速强度 2.2 → 3、下坡重力 0.9 → 1.2、阻力减半。
- **侧身横向滑行（trim）**：在浪面上，浪决定你朝岸方向的速度（跟住浪），板头和浪的夹角决定沿浪峰横向的速度，叠加起来：
  斜着滑比直冲更快（速度 = 朝岸速度 / cos 夹角，最大夹角约 72°），并且不会冲出浪面掉进平水区。超过板子极速时只削减横向速度，不削减跟浪的速度。
  辅助开启时浪峰附近（浪面变平处）仍保留一部分推力，滑到浪峰或较矮的肩部不会立刻丢浪；白水（已破碎的浪）不再把人卷翻，而是推着你一路滑向岸边（落下的浪唇仍会）。
- 起乘提示和滑行时的操作提示改为说明"A / D 侧身沿浪横向滑行"。
- 实测（用户的 Chrome，默认海况 + 辅助，6 个离岸距离最长的破浪点，起乘后不再操作，板子是用户当前的枪板）：
  | 起乘后方向 | 平均时长 | 平均距离 | 平均速度 | 最高速度 | 板子下落高度 |
  |---|---|---|---|---|---|
  | 直冲向岸 | 19.1 s | 95 m | 5.3 m/s | 8.2 m/s | 2.2 m |
  | 斜 35° | 10.0 s | 55 m | 6.9 m/s | 8.2 m/s | 1.6 m |
  | 斜 60° | 8.8 s | 74 m | 8.3 m/s | 12.5 m/s | 1.5 m |
  （改动前同样条件：直冲平均 2.9 m/s；斜 60° 只能滑 3–5 s。斜滑时固定方向不修正，最终会滑出浪峰，实际玩时用 A / D 回切即可。）
